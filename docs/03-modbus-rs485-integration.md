# 03. Интеграция по Modbus/RS-485

## Архитектура

```
Щиты "Смарт Контрол" (Евровент) -- RS-485 (Modbus RTU) --> КУН-IP8 -- Ethernet --> Коммутатор -- Ethernet --> ПК диспетчера (Tekon OPC-сервер -> АСУД.SCADA)
```

Важно: **КУН-IP8 сам не опрашивает устройства** — он прозрачно транслирует запросы от ОРС-сервера (на ПК) на шину RS-485. Вся логика опроса (что, как часто) настраивается в конфигураторе ОРС-сервера, не в самом концентраторе.

## Варианты подключения (по документации)

1. **Modbus TCP напрямую по сети** — DA \ Компьютерная сеть \ Modbus TCP (не наш случай — щиты на RS-485)
2. **Modbus RTU через концентратор КЦС-IPM/КУН-IPM** — DA \ Концентратор КУН-IP8 \ Modbus RTU — **наш вариант**
3. **Modbus RTU через IP/RS-конвертер** — альтернатива, если КУН-IP8 не используется
4. **OPC DA Ext** — если у щитов есть собственный OPC-сервер (Внешний OPC-сервер → Tekon OPC-сервер → АСУД.SCADA), тоже требует лицензии EXT-2

## Требования

- USB-ключ защиты АСУД.SCADA с числом лицензий EXT-2 = число опрашиваемых устройств (в проекте — 9, соответствует смете)
- Уникальный Modbus-адрес (slave ID) на каждом щите в пределах одной линии RS-485
- Одинаковые параметры порта (скорость, чётность, стоп-биты) у всех устройств на линии
- Топология "шина" (не звезда), терминаторы 120 Ом на обоих концах линии (в т.ч. на КУН-IP8 при необходимости — перемычки Term0/Term1 на плате)
- До 255 устройств на интерфейс (уточнять по спецификации конкретного щита)

## Таблица регистров Modbus — БЛОКЕР

**Без таблицы регистров конкретного устройства настройка невозможна** (цитата из документации Текон). Таблица индивидуальна для каждого типа устройства.

Что нужно запросить у ООО «НТЦ Евровент» по каждому типу щита "Смарт Контрол" (ШУ-С4Ч-S1000-00-01-IP31, ШУ-С1,1Ч-S0000-00-00-IP31 и др.):

- [ ] Тип протокола (RTU подтверждён по интерфейсу, уточнить версию Modbus)
- [ ] Параметры порта: скорость (baud rate), чётность, стоп-биты
- [ ] Modbus-адрес (slave ID) по умолчанию / как выставляется
- [ ] Карта регистров: адрес, тип (Coil/DiscreteInput/HoldingReg/InputReg), тип данных (BIT/WORD/FLOAT и т.д.), доступ R/W, множитель, описание сигнала

## Ключевые параметры регистрации в ОРС-сервере (шпаргалка)

| Параметр | Смысл |
|---|---|
| Регистр | Тип: Coil / DiscreteInput / HoldingReg / InputReg |
| Адрес | Физический адрес регистра (можно в hex через $) |
| Тип данных | BIT, BOOL, WORD, SHORT, FLOAT, DWORD, INTEGER, STRING, ARRAY и др. |
| Блок/Бит | Номер бита при разборе битовой маски |
| Формат | Порядок байт/регистров (обычно 1 для 1-регистровых, 4 для 2-регистровых) |
| Множитель | Коэффициент пересчёта в реальное значение |
| AW | Разрешение записи: 0-запрещено, 1/6/10-разрешено (см. функцию записи) |
| Тег | Имя сигнала в SCADA |
| Название | Название для журнала событий |

## Проверка после регистрации устройства

Кнопка "Опросить" в окне настройки устройства → значения появляются в столбце "Значение". Кнопка "Лог" → коды ошибок обмена. Финальная проверка — изменить реальный параметр на объекте и убедиться, что значение меняется синхронно.
